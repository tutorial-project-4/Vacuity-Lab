# 보스 2(수감자) 개발 정리

> 기준 문서: `Assets/Docs/Boss-2-Plans-for-Details.pdf` (2026-08-02 작성본)  
> 작성 목적: 구현 범위, 기존 코드 재사용 지점, 개발 순서, 기획 확인이 필요한 항목을 확정한다.  
> 주의: 아래의 **질문 필요** 항목은 답을 받기 전 임의로 확정하지 않는다.

## 1. 기획 이해 요약

- 보스는 총 HP 1,500이며 중앙 플랫폼에 고정된다.
- 1페이즈는 HP 1,500~801, 2페이즈는 HP 800~1로 해석한다. 누적 700 피해를 받아 HP가 800이 되는 순간 2페이즈로 전환한다.
- 기본 공격은 `확산탄 → 조준탄` 반복이다.
- 조건을 만족하면 현재 패턴 뒤에 예약 패턴을 우선순위대로 실행한다.
  1. 드론 소환(2페이즈)
  2. 저격 패턴(벽 넉백 1회당 조준탄 2회)
  3. 광분 패턴(보스 반경 5타일 안에 연속 10초 체류 시 확산탄 3회)
  4. 기본 패턴
- 벽 러시는 보스 패턴과 독립된 15초 주기의 환경 기믹이다. 구멍이 있는 벽 3개가 오른쪽에서 왼쪽으로 이동하며, 벽 자체는 피해 없이 왼쪽 넉백만 준다.
- 벽 러시 중에만 왼쪽 끝 가시 벽이 활성화되며 접촉 시 체력 1개 피해를 준다.
- 2페이즈는 1페이즈의 모든 요소를 유지하고 드론 소환만 추가한다.
- 드론은 플레이어를 추적하고 직접 피해를 주지 않으며, 반경 3타일 안에서 플레이어 속도를 낮춘다.
- 주사기 거절 → 모든 문 폐쇄 → 중앙 플랫폼 상승 완료 후 보스 공격과 벽 러시 타이머가 시작된다.
- 거리 환산은 `1타일 = Unity 월드 1유닛`이다.
- 페이즈 전환 중 기존 공격은 제거하고 보스의 행동과 피격을 막는다. 플레이어는 이동과 모션을 사용할 수 있지만 보스에게 피해를 줄 수 없다.
- 드론은 시간으로 사라지지 않고 HP가 0이 될 때만 제거된다.

## 2. 현재 프로젝트와 연결할 수 있는 부분

| 요구 기능 | 현재 코드 | 적용 방향 |
| --- | --- | --- |
| 보스 HP/피격/사망 이벤트 | `BossHealth` | 최대 HP와 페이즈 기준을 인스펙터 값으로 설정해 재사용 |
| 보스 체력 UI | `BossHealthGauge` | 그대로 연결 |
| 플레이어에게 1 피해 | `PlayerDamageSource` + `PlayerHealth` | 조준탄·확산탄·가시 벽에 재사용 |
| 보스 행동 그래프 | Unity Behavior, `BossBrain.asset` 및 기존 액션들 | 보스 2 전용 그래프를 만들고 공용 가능한 최소 액션만 재사용 |
| 컷신 중 입력 잠금 | `PlayerController.SetCutsceneLock` | 진입/플랫폼 상승/사망 처리에 재사용 |
| 플레이어 넉백 | `PlayerController.ReceiveHit` | 현재 API는 피해와 결합되어 있어 무피해 벽 넉백에는 그대로 쓸 수 없음 |
| 벽뚫대시 | `PlayerWallPhaseDash`, `DashPassableWall` 규약 | 이동 벽을 통과 가능한 지형으로 구성하고, 벽 넉백 판정에서 대시 상태를 확인 |
| 문/오브젝트 활성화 | `DialogueInteractionAction` 계열 | 선택 결과를 받을 수 있게 확장한 뒤 문 폐쇄와 전투 시작에 연결 가능 |
| 보스전 재시작 | 보스 1의 `Boss.ResetForRetry` 흐름 | 상태 리셋의 참고는 가능하나 보스 2 전용 전투 컨트롤러가 필요 |

현재 프로젝트에는 회색 상자 `Boss-2` 프리팹과 기본 원거리 공격 BT가 있다. 전용 그래픽·애니메이션, 드론·벽 러시 프리팹은 아직 없으며 기준 씬 `semi-complete-arena.unity`의 최종 3×3 아레나 규격도 확정되지 않았다.

## 3. 최소 구현 구조

보스 1의 이동형 공격 코드를 억지로 확장하지 않고 아래 역할만 분리한다.

### 3.1 전투 컨트롤러

`Boss2BattleController` 하나가 다음 상태와 타이머를 소유한다.

```text
대기 → 문 폐쇄/플랫폼 상승 → 1페이즈 → 2페이즈 → 보스 사망
                                  └ 플레이어 사망/재시작
```

- 보스 HP 800 진입을 1회 감지해 2페이즈를 시작한다.
- 페이즈 전환 시 진행 중인 공격을 제거하고 보스 AI와 피격을 잠근다. 플레이어 조작은 유지하되 플레이어 공격이 보스 HP를 줄이지 못하게 한다.
- 보스 패턴 실행, 벽 러시 타이머, 드론 소환 타이머를 시작·정지·초기화한다.
- 보스 사망 시 모든 탄환, 이동 벽, 드론, 예약 패턴과 타이머를 정지한다.
- 문·중앙 플랫폼·보스 UI·플레이어 입력 잠금 참조를 가진다.

### 3.2 보스 패턴 실행기

- 보스는 이동하지 않으므로 이동 AI는 만들지 않는다.
- 기본 패턴은 확산탄 1회 후 조준탄 1회다.
- 광분/저격/드론은 단순 예약 플래그 또는 예약 횟수로 관리한다.
- 한 행동이 끝날 때 `드론 → 저격 → 광분 → 기본` 순으로 다음 행동을 고른다.
- 벽 러시는 별도 코루틴으로 실행해 보스 공격을 중단하지 않는다.

복잡한 범용 우선순위 시스템이나 새 FSM 프레임워크는 만들지 않는다. 보스 2에 실제로 존재하는 네 가지 우선순위만 코드에 둔다.

### 3.3 공격/환경 구성

| 구성품 | 구현 기준 |
| --- | --- |
| 확산탄 | 발사 순간 플레이어가 있는 좌/우 반구 선택 → 반구 안에서 중심각 무작위 선택 → 중심각 기준 15° 간격 5발 동시 발사. 속도 `0.85 × 플레이어 기본 이동속도`, 1회 피해 후 제거, 중앙에서 인접 플랫폼 영역까지 가면 제거 |
| 조준탄 | 경고 시작 시 플레이어 방향 고정 → 0.65초 경고 → 속도 `1.00 × 대시 평균속도`로 맵 밖까지 이동 → 1회 피해 후 제거 → 0.8초 후딜 |
| 이동 벽 | 우측 밖에서 구멍 프리팹 3개를 순차 생성, 속도 3타일/초, 좌측 밖에서 제거. 일반 대시는 막고 벽뚫대시는 통과. 접촉 시작마다 왼쪽으로 2.5타일/0.25초 넉백, 접촉 유지 중 중복 넉백 없음 |
| 가시 벽 | 첫 이동 벽이 아레나에 진입할 때 켜고 마지막 벽이 퇴장할 때 끈다. `PlayerDamageSource(1)` 사용 |
| 드론 | 보스 위치에서 1체 생성, HP 60, 속도 2타일/초로 추적, 플레이어와 1타일 간격 유지 시도, 접촉 피해 없음, 피격 넉백 적용, 반경 3타일 감속. 시간 제한 없이 HP 0에서만 제거 |

탄환과 이동 벽은 프리팹을 생성하되, 초기 버전에는 오브젝트 풀을 만들지 않는다. 프로파일링에서 실제 GC/생성 비용 문제가 확인될 때만 풀을 추가한다.

## 4. 개발 전 필요한 기획/리소스

### 반드시 필요한 씬 기준값

- 거리 환산은 `1타일 = Unity 월드 1유닛`으로 확정
- 3×3 각 플랫폼의 중심 좌표, 폭·높이, 플랫폼 간 거리
- 중앙 플랫폼의 시작/전투 위치와 상승 시간
- 아레나 좌우·상하 경계, 탄환 제거 경계, 이동 벽 생성/제거 X좌표
- 이동 벽 구멍의 폭과 가능한 구멍 위치/프리팹 목록
- 왼쪽 가시 벽의 위치와 판정 크기

### 필요한 제작 리소스

- 보스 2 스프라이트, 기본/발사/소환/피격/사망 애니메이션
- 중앙 플랫폼 상승 연출
- 확산탄·조준탄 및 조준 경고 비주얼
- 이동 벽 프리팹과 구멍 변형들, 가시 벽 비주얼
- 드론 스프라이트, 이동/피격/사망 및 감속 범위 표현
- 공격·경고·벽 러시·드론 소환 사운드
- 주사기 선택 UI/대사 및 보스전 전후 스토리 연출

### 추가 문답으로 확정된 구현 기준

- 확산탄은 정해진 이동거리(중앙에서 다음 플랫폼 영역까지)를 채우거나 플레이어에게 명중하면 제거한다.
- 조준탄은 맵 밖으로 나가거나 플레이어에게 명중하면 제거한다.
- 두 탄환의 경고는 이동 궤적 표시 방식이라는 답변을 받았다. 단, 확산탄은 원 기획의 “별도 경고 없음”과 충돌하므로 아래 P0에서 다시 확인한다.
- 이동 벽 프리팹과 구멍 배치는 아직 미정이다. 프로토타입은 임시 벽 한 종류로 검증하고 확정 리소스가 나온 뒤 교체한다.
- 페이즈 전환 중 기존 공격은 제거한다. 보스는 행동·피격 불가, 플레이어는 이동과 모션이 가능하지만 보스에게 피해를 줄 수 없다.
- 플레이어 사망 후 기존 보스 1과 같은 사망 UI를 거쳐 타이틀로 돌아간다. 보스 2 조우 조건을 얻은 뒤 빠른 시작을 선택하면 보스 2 방 안의 전투 시작 전 위치에서 재개한다.
- 드론은 별도 수명 없이 피격으로 HP가 0이 될 때만 제거한다.

## 5. 기획자에게 질문할 내용

### P0 — 답이 없으면 구현 기준을 정할 수 없는 항목

1. **벽 생성 간격(해결):** 기획자 재확인 결과 첫 벽 이후 `1.50초 간격`, 즉 `0초/1.50초/3.00초`로 확정했다.
2. **드론 첫 소환 시점:** 8.1에는 `2페이즈 진입 즉시`, 같은 절 설명과 검수 기준에는 `2페이즈 시작 30초 후`로 적혀 있습니다. 즉시 1체를 소환하고 그다음부터 30초인지, 첫 소환도 30초 후인지 확인이 필요합니다.
3. **드론 감속 하한:** “곱연산 중첩을 하되 30% 상한”이라고 답했지만 예시 `0.7³ = 0.343`은 원래 속도의 34.3%, 즉 65.7% 감속입니다. `각 드론이 30%씩 곱연산`하는 것이 맞나요, 아니면 최종 속도가 원래 속도의 70% 아래로 내려가지 않아야 하나요?
4. **아레나 규격:** `1타일 = 월드 1유닛`은 확인되었습니다. 남은 3×3 플랫폼의 실제 중심 좌표·크기·간격과 벽/탄환 생성·제거 경계를 확정해 주세요.
5. **이동 벽 프리팹:** 구멍 배치가 미정인 동안 임시 벽 한 종류로 개발해도 되나요? 최종적으로 필요한 구멍 종류, 폭, 한 러시 내 중복 허용 여부는 언제 확정되나요?
6. **페이즈 전환:** 기존 공격을 “잠시 제거”한다고 했는데 탄환·이동 벽·가시 벽·드론을 모두 삭제한다는 뜻인가요? 전환 시간과 전환 종료 후 벽 러시/드론 소환 타이머를 처음부터 다시 세는지도 필요합니다.
7. **플레이어 사망/빠른 시작:** 타이틀로 돌아가는 흐름은 확인되었습니다. 보스 2 빠른 시작이 열리는 정확한 시점, 로드할 씬, 스폰 위치, 복원할 스킬·스토리 플래그를 지정해 주세요. 재진입 시 보스 HP·문·플랫폼·탄환·벽·드론·예약 패턴은 모두 초기 상태로 해석해도 되나요?
8. **확산탄 경고 충돌:** 추가 답변은 탄환 발사 전에 이동 궤적을 표시한다고 했지만 원 기획 5.1과 검수 06은 확산탄에 별도 경고가 없다고 합니다. 궤적 경고는 조준탄만인가요, 확산탄도 0.15초 선딜 동안 표시하나요?

### P1 — 전투 동작과 난이도에 직접 영향이 있는 항목

9. **확산탄 각도:** 오른쪽 반구의 중심각 범위를 `-60°~+60°`, 왼쪽을 `120°~240°`로 적었지만, 5발 전체가 반구 안에 있으려면 중심각 가장자리 제한이 필요합니다. Unity의 0°=오른쪽 기준으로 중심각을 오른쪽 `-60°~+60°`, 왼쪽 `120°~240°`에서 그대로 뽑아도 되는지, 아니면 60° 부채꼴 전체가 좌/우 180° 반구 안에 들도록 좁혀야 하나요?
10. **확산탄 사거리:** “중앙 플랫폼에서 다음 플랫폼 영역까지”의 종료 기준은 탄환 중심이 인접 플랫폼 셀 경계에 닿을 때인가요, 아레나 외곽까지인가요? 도식 또는 타일 거리 수치가 필요합니다.
11. **탄환과 지형:** 플레이어 명중 및 이동거리/맵 이탈 제거 조건은 확인되었습니다. 플랫폼과 이동 벽은 통과하는지, 물리적으로 막히되 제거되지는 않는지 필요합니다. 드론이나 다른 탄환과의 충돌 여부도 확인해 주세요.
12. **보스 몸체 접촉:** 중앙의 보스/중앙 장치에 닿았을 때 플레이어 피해·넉백·충돌이 있나요? 플레이어가 중앙 플랫폼에 올라설 수 있는지도 확인해 주세요.
13. **벽 넉백 방향/충돌:** 2.5타일을 0.25초 동안 강제 이동할 때 플레이어 조작, 중력, 점프/대시가 잠기나요? 다른 지형에 막히면 중단되나요? 넉백 중 가시 벽에 닿으면 즉시 피해를 받나요?

## 6. 권장 개발 순서

1. **P0 답변과 아레나 수치 확정** — 상충 수치와 좌표를 먼저 잠근다.
2. **회색 상자 아레나** — 3×3 플랫폼, 중앙 상승 플랫폼, 문, 생성/제거 경계만 배치한다.
3. **전투 시작/종료 골격** — 주사기 거절 신호 대신 임시 테스트 트리거로 문 폐쇄 → 상승 → 전투 시작 → 사망 정지를 검증한다.
4. **기본 패턴** — 확산탄과 조준탄, `확산탄 → 조준탄` 반복을 구현한다.
5. **벽 러시** — 벽 3개, 벽뚫대시 통과, 무피해 넉백, 가시 벽, 보스 패턴과 공존을 구현한다.
6. **예약 패턴** — 광분 누적/초기화, 저격 이벤트/예약, 우선순위를 구현한다.
7. **2페이즈와 드론** — 페이즈 전환, 소환 타이머, 추적/HP/넉백/감속을 구현한다.
8. **선택·재시작·스토리 연결** — 실제 주사기 선택과 사망/보스 사망 흐름을 연결한다.
9. **아트·사운드 교체 및 튜닝** — 확정 리소스를 넣고 실제 플레이어 속도 기준으로 비율 수치를 계산한다.

각 단계는 새 기능 하나와 해당 기능을 깨뜨리면 실패하는 최소 검증 시나리오 하나만 추가한다.

- 확산탄은 0.15초 선딜 후 발사 순간 플레이어가 있는 좌/우 반구를 선택한다. 오른쪽은 `-60°~+60°`, 왼쪽은 `120°~240°`에서 중심각을 균등 무작위로 뽑고 `-30°, -15°, 0°, +15°, +30°`의 5발을 동시 발사한다.
- 확산탄에 `spreadWindup=0.15`와 한국어 툴팁을 추가했으며 선딜 중 별도 경고선은 표시하지 않는다.
- 조준탄의 방향 고정, 0.65초 경고, 0.8초 후딜은 유지했다. 확정된 보스 2 아레나 제거 경계가 없어 `aimedRange=40`도 임의로 바꾸지 않았다.
- 누락됐던 `Boss2IntroTrigger.cs`를 씬 참조 GUID `45202957fc613a0439c15bfb7c9c6d40` 그대로 복구했다. 플레이어 Trigger 진입 시 지정된 비활성 `Boss-2`만 한 번 활성화한다.
- `Boss-2.prefab.meta`의 GUID `72aeed449c0902b4a994b9dc6b93d1bf`와 씬 프리팹 참조가 일치함을 확인했다.
- `Boss2Controller.AttackLoop()`를 제거하고 기존 인스펙터 값·한국어 툴팁·발사체 정리 기능은 유지했다.
- 보스 2 전용 `Boss 2 Spread Shot`, `Boss 2 Aimed Shot` Behavior Action을 추가했다.
- `Boss2Brain.asset`은 반복 Start 아래 `확산탄 → 조준탄` 순서로 구성했고 `Boss-2.prefab`의 `BehaviorGraphAgent`에 연결했다.
- `Boss2Controller.AttackLoop()`는 제거했으며 발사·경고선·생성물 정리만 담당한다.
- `Boss2BehaviorSetup`의 씬·프리팹 검증을 통과했다. Editor 로그의 최종 결과는 `BOSS2_SETUP_PASS`다.
- 보스 2 프리팹에는 보스 1의 `Boss`, `BossArenaController`, `BossBrain.asset`이 연결되어 있지 않다.
